# Change Log

## 2026-11-14

- Created Brushline from the UBC-FRESH dev workflow seed. The agent contract, roadmap, docs skeleton, and validator came from the seed. Every phase is planned, and no parent issues exist yet.
- P0.1: adapted the operating contract and repository identity. `AGENTS.md` now carries the domain rules for segments, uncertain vegetation states, treatment transitions, monitoring decisions, the shared plan artifact, the `fresh-solutions` adapter, exact replay, the artifact-reading studio, adapters, safety, and provenance. Added `README.md`, `CONTRIBUTING.md`, `LICENSE` (Apache-2.0), `CODE_OF_CONDUCT.md`, and `CITATION.cff`, and set the repository description and topics. Dashboard result: `python scripts/dashboard.py` reports `OVERALL: GREEN` on lint, format, types, tests, validator, and docs.
- P0.2: made Brushline an installable package with a tested command line. Added `brushline/__init__.py`, `brushline/cli.py` with `--version` and `status`, the `[project]` metadata and `brushline` console script, the runtime dependencies, the `geo`, `opt`, and `web` extras, the API page, and `tests/test_brushline_cli.py`. CI and the docs build install the package in editable mode. `python -m pip install -e .`, `brushline --version`, and `brushline --help` work. Dashboard result: `python scripts/dashboard.py` reports `OVERALL: GREEN`; test coverage is 100 percent.
- P0.3: wrote the scope in `notes/design/brushline-scope.md`. It states the corridor vegetation problem, the users and decisions at strategic, tactical, and operational scales, the owner-contractor value proposition, the NP-hard optimization claim, the open LiDAR and low-vegetation calibration gap, the FEMIC-extended instance builder, the demo portal, the in-scope and out-of-scope items, sixteen observable success criteria, the constraints, and the open questions with their resolving phases.
- P0.12: reviewed open shrub and young-tree growth models in `notes/reference/shrub-young-tree-growth-models.md`. The review assesses 18 candidate models and families, including MEDFATE (the closest open shrub-cohort model, GPL/LGPL, R/C++, Mediterranean stand scale), FVS/FFE (public domain, but live herb and shrub fuels are not dynamically simulated), LANDIS-II (Apache-2.0 landscape cohorts), ST-Sim (CC BY-ND, not derivable), VDDT/Path, FireBGCv2, TASS, VDYP/TIPSY, PHYGROW, Botequim et al. shrub biomass, ORCHIDEE/LPJ-GUESS/ED2, powerline tree-growth and LiDAR tools, PLS-CADD, and the BC Hydro IVMP. It records reusable components, the from-scratch rationale for the segment-level state-transition core, the validation plan, and what would change the decision. Added `notes/reference/codex-library-search-prompt.md` for the paywalled and grey literature.
- P0.4: wrote the architecture in `notes/design/brushline-architecture.md` and twelve ADRs in `notes/adr/0001` to `notes/adr/0012`. The architecture covers the system context, the corridor and segment model, the uncertain vegetation state, growth and treatment transitions, hazards, the three-scale planning stack, the Fresh Solutions adapter and Pareto archive, plan and bid exchange, the FEMIC-extended instance builder, the artifact contracts, the studio and demo portal, the integration boundaries, performance, security, and open questions. The ADRs lock segments as the decision unit, state as a distribution, treatments as transitions, the shared three-scale contract, monitoring as a decision, the Fresh Solutions adapter, the artifact-reading studio, FEMIC as LiDAR producer and instance builder, the low-vegetation model decision, the public demo boundary, provenance, and agent capabilities.
- P0.5: replaced the seed roadmap with the Brushline phase map in `ROADMAP.md`. The map covers P0 bootstrap and scope, P1 contracts and prototype, P2 the FEMIC-extended instance builder, P3 state/LiDAR/terrain, P4 vegetation dynamics, P5 optimization and Pareto search, P6 strategic planning, P7 tactical and operational planning, P8 monitoring and adaptive replanning, P9 plan and bid exchange, P10 the planning studio, P11 the demo portal, P12 verification and the BAU case, P13 release, and P14 operations. Each phase has a goal, tasks, and observable acceptance criteria; P0 is the only active phase.
